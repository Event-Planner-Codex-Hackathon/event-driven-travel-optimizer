# Backend review — 12 October 2026

Scope: the uncommitted v1.2 additions on `onur/backend-planner`, plus the existing paths they exercise. No real-key calls, observations from a provider, frontend edits or paid calls were used in this review. Findings below are ordered by impact. File/line references point to the correction in the reviewed tree; the scenarios describe the prior behavior.

| Priority | File:line | Concrete failure scenario | Correction and regression coverage |
| --- | --- | --- | --- |
| P1 | `src/server/trips.ts:307` | Reoptimize with `changes.event.endDate` one day earlier, or `changes.event.city = Bangkok`, changed the original hard constraint before the independent checker ran. | Reject changes to locked event identity/city/dates with `400 invalid_body`, including `baseRequest` fallback. Service and HTTP tests cover rejection and unchanged-event acceptance. |
| P1 | `src/server/providers/runtime.ts:60` | Switch from live to replay in one process: shared cache/in-flight keys could serve live data in replay, or replay data in live mode, without consulting the selected provider. Record mode could reuse a live cached response without saving it. | Namespace caches/in-flight calls by mode and observation directory. Regression switches modes without resetting caches. Invalid modes fail closed. |
| P1 | `src/server/pricing.ts:89`, `:114` | A first check replaces a 20,000 TRY estimate with a 100 TRY provider result. A failed second check kept 100 TRY but relabeled it heuristic/mock and erased its provenance. | Rebuild genuine flight/hotel estimates on failed repricing, including modeled durations/stops. Regression checks line amounts, totals and removed source fields against the initial estimate plan. |
| P1 | `src/server/events.ts:119`, `:204` | Google lists no year or an unreadable multi-day end; Ticketmaster omits the end. The adapter guessed a year or one-day duration, then emitted plannable event overrides. Explicit years were also ignored. | Missing year/end becomes partial and cannot be planned directly. Preserve explicit years, including cross-year ranges; reject reversed explicit ranges. Tests cover each case. |
| P1 | `src/server/providers/observations.ts:90` | A copied/corrupt recording with a mismatched query, USD price, null offer or invalid timestamp was accepted as provider-priced TRY data, corrupting totals or crashing pricing. | Validate version/provider/kind/query, offer shape, positive safe-integer TRY prices, chronology and observation time; discard noncanonical URLs. Atomic writes avoid partial JSON reads. Corrupt-recording regressions fail closed. |
| P2 | `src/server/events.ts:33`, `:230`, `:346` | New guest cookies could keep Ticketmaster/Eventbrite searches running without a process-wide cap; failed attempts also consume external quota. | Each provider gets a configurable rolling hourly process cap (default 40). Count attempted failures; local cap blocks refund the guest reservation. Tests cover exhaustion and HTTP refund with no outbound call. |
| P2 | `src/server/events.ts:252` | Two concurrent identical event searches missed the cache and each spent a provider search. | Share in-flight results; only the initiating request is metered. Concurrency test observes one fetch and `[1, 0]` metered calls. |
| P2 | `src/server/events.ts:208`, `:318` | A venue in London, Canada matched the catalog's London, GB despite the provider's country code, yielding flights to the wrong country. | Reject conflicting country matches for Ticketmaster and Eventbrite. Regression preserves the unsupported venue without plannable overrides. |
| P2 | `src/server/providers/weather.ts:67` | A syntactically valid range ending in year 9999 allocated millions of dates before enforcing the 21-day limit. | Check date difference before allocation; enormous-range regression returns a validation error. |
| P2 | `src/server/trips.ts:315`, `src/app/api/trips/[requestId]/price-check/route.ts:31` | After a restart, a client displaying version 8 got version 2/3, so its stale-response guard could discard the new result. Price-check fallback also incremented twice. | Add optional `baseRequirementsVersion` and increment once from it. Service/HTTP tests cover version 8→9. Legacy callers may omit it; restart limitation is documented. |
| P2 | `src/server/providers/fx.ts:27`, `src/server/trips.ts:311` | FX rates with different publication dates were presented as one snapshot; changing only the optional city erased the foreign-budget conversion assumption. | Require a common valid reference date; retain dated budget-conversion provenance when the budget is unchanged. Both cases have regressions. |
| P2 | `src/server/comparison.ts:17` | All-provider live and replay options were marked comparably priced, despite different retrieval provenance. | Include retrieval mode in the pricing signature; mixed sources remain indicative. |
| P2 | `src/server/providers/weather.ts:43` | A provider day containing only null values was labeled `forecast` despite having no usable forecast. | Mark missing core values or invalid weather codes unavailable. Regression covers null daily values. |

Additional hardening: malformed event collections are ignored, Eventbrite URLs require HTTPS and an expected domain/path, event deduplication includes city/end date, new session-limit typing stays optional for compatibility, and recorded provider files are Git-ignored pending terms review and explicit sharing approval. The duplicate untracked `vitest.config.ts` shadowed the tracked `.mts` config; its original was moved to `/tmp/eventhopper-duplicate-vitest.config.ts` and the tracked config is used.

Verification: `npm test` — 8 files, 87 tests passed. `npm run typecheck` — exit 0, no diagnostics. `npm run build` — exit 0, optimized compilation, TypeScript and all 10 static pages completed. No real provider integration is established by these tests. Record/replay tests use explicitly synthetic adapter data in temporary directories, never committed observations.

Remaining integration limits: state, quotas and Fal job deduplication are process-local; fallback event identity trusts the client when no stored trip exists; clients must supply the latest base version after memory loss. Free-plan provider account quota and no-paid-overage settings must be confirmed before real-key validation. Real SerpApi/Ticketmaster/Eventbrite/Fal response compatibility and actual record/replay demo rehearsals remain pending the user's credential-ready signal.
